## 〇、总体结论

经逐页核对规范 PDF 原文，系统的**核心判定框架整体符合规范**：表 4.3.1 查表数值、表 3.2.4 分级数值、5.2.1 平面交叉判定、4.2.1 横向预留、B.2 横向稳定性、各净空阈值等均已核准无误。**唯一需要更正的重大点是液压挂车 B.1.2-4/5/6 扫空闭式解的线性近似与规范原式存在实质差异（见问题1与附录A）**。

但存在 **1 个可能直接导致判定失真的核心问题（P0）** 与 **若干口径/完整性修正项（P1）**，以及**画图/方法增强项（P2）**。以下按优先级给出可落地修改方案。

## 一、P0 —— 直接影响判定正确性

### 问题1：液压挂车 B.1.2 系列公式与规范不符（轮迹半径 R外/R内、扫空闭式解 Rmin/Rmax/Wd）★核心

- **位置**：
  - `app/core/kinematics.py` `hydraulic_turn_radii()` 第 218-264 行
  - 消费方 `app/core/passability.py` 圆弧判定第 369、402 行
- **规范原式（用户截图确认，见附录A）**：
  - (B.1.2-2) `R_内 = L轮挂(Na−1)/(2tanθ)`
  - (B.1.2-3) `R_外 = sqrt( [L轮挂(Na−1)/(2tanθ) + La]² + [L轮挂(Na−1)/2]² )`
  - (B.1.2-4) `Rmin = L轮挂(Na−1)/(2tanθ) − (D总−d)/2`
  - (B.1.2-5) `Rmax = sqrt( [L轮挂(Na−1)/(2tanθ) + (D总+d)/2]² + [L轮挂·Na/2 + C]² )`
  - (B.1.2-6) `Wd = Rmax − Rmin + σ`
- **代码现状 vs 规范差异表**（`base = d/(2tanθ)`，`d = L轮挂·(末−首 有效轴距)`）：

  | 量 | 代码（线性近似） | 规范原式 | 差异 |
  |---|---|---|---|
  | R_in / Rmin | `base + (D总−d)/2` | `base − (D总−d)/2` | **横项符号相反** |
  | R_out / Rmax | `base + (D总+d)/2` | `sqrt[ (base+(D总+d)/2)² + (L轮挂·Na/2 + C)² ]` | **漏勾股横项、漏动力机组长 C** |
  | W_swept / Wd | `= d` | `Rmax − Rmin + σ` | **漏安全宽度 σ，且 Rmax/Rmin 基础不同** |
  | W_turn | `d + 0.5` | 基于 (B.1.2-1) `R外 − R内 + 0.5` | 用扫空基数 d 代替轮迹通道宽 |
- **影响**：当前闭式解是明显线性化近似。规范下 Rmin **更靠近圆心**（内缘更占道）、Rmax **更大**（勾股含动力机组），扫空宽度 `Wd` 需再 **+σ**。即规范判定比代码**更保守**；代码存在高估通行能力、低估占道宽度的风险，遗漏动力机组长度 C。
- **改法（推荐，严格按规范重写闭式解）**：
  1. 重写 `hydraulic_turn_radii` 中 `r_in / r_out / w_swept / w_turn`，严格落 (B.1.2-4)/(B.1.2-5)/(B.1.2-6)：
     ```python
     base = L * (na - 1) / (2.0 * math.tan(theta))
     r_min = base - (d_total - d) / 2.0                  # B.1.2-4
     r_max = math.hypot(base + (d_total + d) / 2.0,
                        L * na / 2.0 + power_unit_len)    # B.1.2-5，含横项+C
     w_swept = r_max - r_min + TURN_SAFE_CLEARANCE_B12    # B.1.2-6，+σ
     ```
  2. `power_unit_len` 取 `bundle.trailer.power_unit_length`（动力机组长度，默认 0.0 时退化为无 C）。
  3. "转弯通道宽度" `w_turn` 依 (B.1.2-1) 用轮迹半径 `R外(c)-(3) − R内(c)-(2) + 0.5` 单独计算，**不再复用扫空宽度**。
- **改动落点**：
  - `kinematics.hydraulic_turn_radii()` 重写 `r_in/r_out/w_swept/w_turn`，返回新增 `R_vehicle_in/R_vehicle_out`（轮迹）与 `power_unit_len`；`W_swept` 改为 `Wd`（含 σ）。
  - `passability.py:369` 用新 `w_swept`、`turn_channel_w`。
  - `config.py` 增 `TURN_SAFE_CLEARANCE_B12`（=0.5，已按截图把 σ 语义写明）；新增 `POWER_UNIT_LENGTH` 回退默认。
- **验证**：`tests/test_passability.py` M6 用例：① 中等动力机组长度的液压车，`Rmax` 相对旧值增大、`Wd` 含 σ；② 小轴距车在中等车道 `width_ok` 判定更稳妥；③ 锁定 `Wd == Rmax−Rmin+0.5` 与规范一致。

### 问题2：尺寸分级总长度漏算牵引车

- **位置**：`app/core/grade.py` `classify_bundle()` 第 87 行
- **现象**：`total_l = max(trailer.length, cargo.length)`，未加牵引车长度。规范表 3.2.4 的"总长度"为"牵引车+半挂车"整车总长。
- **改法**：
  ```python
  total_l = max(tl.length, cargo.length) + tractor_length
  ```
  - `tractor_length` 取 `bundle.tractor.length`；（当前 `trailer.length` 语义为挂车本体长、`tractor.length` 为牵引车长，两者相加即整车总长）。
  - 避免重复计入：若以后 `trailer.length` 改为整车全长则不再加。
  - 货物前端外伸 / 耦合段是否计入以整车最大外廓为准，逐案 `max` 进 `total_l`。
- **验证**：M5 分级用例补一条：挂车 15 m + 牵引车 8 m 的低平板车，长度档应从 A(≤17) 升为 B((17,22])。

### 问题3：高度档 (4.00, 4.50] 共区统一记 C（偏高）

- **位置**：`app/core/grade.py` `_HEIGHT_BANDS` 第 54-59 行
- **现象**：规范表 3.2.4 中 A/B/C 三行高度同为 `(4.00,4.50]`，代码把该段固定记 C，导致长宽均 A、总高 4.3 m 的车被误判为 C（规范应为 A）。
- **改法**：高度维度不再抢档：
  ```python
  _HEIGHT_BANDS = [
      (float("-inf"), 4.50, "A"),   # ≤4.50 → 高度不抬级，A/B/C 由长宽决定
      (4.50, 5.00, "D"),
      (5.00, float("inf"), "E"),
  ]
  ```
  即高度只在跨越 4.5 / 5.0 边界时抬到 D/E；(4.0, 4.5] 内保持长宽决定的档位。
- **验证**：新增用例——长宽均 A、总高 4.3 m → 判 `A`（当前误判 `C`）。

## 二、P1 —— 口径 / 完整性修正

### 问题4：横向稳定性 μ 语义（横向力系数 vs 衬垫摩擦系数）

- **位置**：`config.py` `PAD_FRICTION`；`app/core/lateral.py` `side_slip_critical_v`；`app/core/passability.py` `_lateral_check()` 第 196 行
- **现象**：规范 B.2.2 的 μ 为"横向力系数"（离心工程系数）；代码以"衬垫摩擦系数"（木板 0.4 / 橡胶垫 0.7…）替代。
- **改法（二选一，推荐①）**：
  - ① 保留衬垫摩擦取值，但把 docstring 与报告文案改为"以衬垫摩擦系数作为横向力系数的**保守下限**"，结论中固定展示"该 μ 为替代口径"。
  - ② 界面新增"横向力系数 μ"独立输入（默认工程值如 0.15~0.20），`_lateral_check` 优先使用，未填时回退衬垫摩擦。需新增 datamodel 字段 + 界面输入 + 面板联动。
- **验证**：M8 保持；新增"μ 取衬垫 vs 独立值"阈值差异断言。

### 问题5：匝道 6.3.2 的 0.25 被当作顶部净空间隙

- **位置**：`app/core/passability.py` `_vertical_check()` 第 162-169 行
- **现象**：规范 6.3.2 的"不宜 <0.5 / 不应 <0.25"是外廓与护栏等之间的**横向预留**；代码却拿"顶部净空 − 车货总高"的**竖向间隙**去对比 0.25，横竖口径混用。
- **改法**：
  - ① 匝道顶部净空改用结构净空通用口径（具体阈值见"四、前置依赖"第 2 项），替换当前的 0.25。
  - ② 把"外廓与护栏横向预留 0.5/0.25"改为横向校核（需引入"匝道路面/可用横向空间"输入）。
  - 若暂不采集匝道横向空间：**推荐**暂不新增横向校核，顶部净空改用结构净空阈值，并在判定文案注明"匝道横向预留 0.5/0.25 未纳入，需专项评估"。
- **验证**：M7 + P0-6 垂直净空用例：匝道场景顶部间隙 0.15 应按新阈值判定。

### 问题6：隧道 9.2.1 只校顶部

- **位置**：`app/core/passability.py` `_vertical_check()` 第 152-160 行；`config.py` 常量已备（`TUNNEL_SIDE_CLEARANCE`、`TUNNEL_HIGH_REQ_BOTTOM`、`TUNNEL_GROUND_CLEARANCE`）
- **观察**：代码注释称侧壁/检修道/底缘在"隧道专项模块（P2）"处理，但仓库未见该模块落地。
- **改法**：
  - 顶部 +（有输入时）侧壁/底缘：侧壁 0.5、货物底高于检修道 0.2、底缘距路 0.2，需额外输入 `隧道可用宽度 / 检修道高`。
  - 若暂不采集这些输入，则在**结论文字中显式输出"侧壁/检修道/底缘净空未纳入本系统校核，需专项评估"**，将缺口结构化呈现而非静默。
- **验证**：P0-6 隧道用例补一条：顶部满足但明确提示侧壁等未校核（断言文案含该提示）。

## 附录A：规范 B.1.2 公式原文（据用户提供截图转录）

> 第 2 款：牵引车+多轴多轮液压悬挂挂车 **转弯通道宽度** 应按式 (B.1.2-1)/(B.1.2-2)/(B.1.2-3) 计算，且应 ≤ 通行道路提供的横向路面宽度。

**(B.1.2-1)**　`W_z = R_外 − R_内 + 0.5`

**(B.1.2-2)**　`R_内 = L轮挂·(Na−1) / (2·tanθ)`

**(B.1.2-3)**　`R_外 = sqrt( [ L轮挂·(Na−1)/(2·tanθ) + La ]² + [ L轮挂·(Na−1)/2 ]² )`

式中：`Na` —— 轴数；`θ` —— 多轴多轮液压悬挂挂车第一轴线内侧轮胎转向角（°）。

> 第 3 款：车货总体**最大扫空空间宽度**应按式 (B.1.2-4)/(B.1.2-5)/(B.1.2-6) 计算，且 Rmin~Rmax 范围内不应存在阻碍悬架与货物通行的障碍物。

**(B.1.2-4)**　`Rmin = L轮挂·(Na−1)/(2·tanθ) − (D总−d)/2`

**(B.1.2-5)**　`Rmax = sqrt( [ L轮挂·(Na−1)/(2·tanθ) + (D总+d)/2 ]² + [ L轮挂·Na/2 + C ]² )`

**(B.1.2-6)**　`Wd = Rmax − Rmin + σ`

式中：`d` —— 多轴多轮液压悬挂挂车轴距（m）；`C` —— 多轴多轮液压悬挂挂车动力机组长度（m）；`σ` —— 安全宽度预留；其余符号同前。

> 符号一致性提示：代码 `base = L·(Na−1)/(2tanθ)` 即规范分子项 `L轮挂(Na−1)/(2tanθ)`；需核对代码是否另有字段承载 `Na`（当前用 `axle_count`）、`d`（当前用 `L·(末−首)` 有效轴距）、`C`（动力机组长度，当前缺失，默认 0）。
