### 2.1 表 3.2.4 总高度分级写错、缺级 —— `app/core/grade.py` ✅1

**问题**：`_HEIGHT_BANDS` 缺 B 级，A/C/D 区间错位。规范为 A/B/C 共区 `(4.00,4.50]`、D `(4.50,5.00]`、E `>5.00`。总宽度需补下限（A `(2.55,3.00]`）。

**改为**：

```python
# 总高度 (m)：A/B/C 共区 (4.00,4.50]，D (4.50,5.00]，E >5.00
_HEIGHT_BANDS = [
    (float("-inf"), 4.00, "A"),
    (4.00, 4.50, "C"),     # B(4.00,4.50] 与 A/C 同值区，由长度/宽度级决定落到 B
    (4.50, 5.00, "D"),
    (5.00, float("inf"), "E"),
]
# 总宽度 (m)：A 补下限
_WIDTH_BANDS = [
    (2.55, 3.00, "A"),
    (3.00, 3.50, "B"),
    (3.50, 3.75, "C"),
    (3.75, 4.50, "D"),
    (4.50, float("inf"), "E"),
]
```

> 说明：`B` 高度与 `A`/`C` 同值区，`classify()` 已按长/宽/高三轴取最高级，故"高度为 A/B/C 区"时由另两轴决定是否落 `B`——**无需在高度表里硬造 B 行**，但必须在本文档与 `test_m5_classify_bounds` 中说明：`classify(10, 2.8, 4.2, False)` 高度落 (4.00,4.50] 但宽/长均 A → 综合为 A 而非 C。**请复核期望值**（原测试期望 `"C"` 在宽度 2.8= A、长度 10=A、高度落 C 区间，按"取最高"应为 A，需修正测试）。

**长度分级**（低平板/液压）本已正确，照规范区间保留 `(lo, hi]` 写法即可。

### 2.2 表 4.3.1 数值错位，把"最大扫空空间宽度"当"最小半径" —— `app/core/grade.py` ✅2

**问题**：`TABLE_4_3_1_RMIN` 把第二列`最大扫空空间宽度`(8.6/11.2/17.7/20.2) 误当第一列`最小半径`，真正的最小半径 11/15/22/28 丢失。规范 4.3.1第1款要求**两列均大于**表值才满足。

**改为**双列存储 + 双条件查表：

```python
# 表4.3.1 圆曲线可通行性（第一列=最小半径m，第二列=最大扫空空间宽度m）
TABLE_4_3_1 = {
    "A": {"min_radius": 11.0, "max_swept_width": 8.6},
    "B": {"min_radius": 15.0, "max_swept_width": 11.2},
    "C": {"min_radius": 22.0, "max_swept_width": 17.7},
    "D": {"min_radius": 28.0, "max_swept_width": 20.2},
    "E": None,   # 表4.3.1 无 E 行 → 回退验算/仿真
}

def arch_lookup_apply(grade, curve_radius, transverse_space_w, swept_w):
    """查表法 4.3.1第1款：半径与通行空间宽度双超表值才判满足。

    返回 "pass" / "fail" / "fallback"（E级或缺数回退验算/仿真）。
    """
    row = TABLE_4_3_1.get(grade)
    if row is None:
        return "fallback"
    r_ok = curve_radius > row["min_radius"]
    w_ok = transverse_space_w > row["max_swept_width"] and swept_w < transverse_space_w
    if r_ok and w_ok:
        return "pass"
    return "fail"     # 触发 B.1 验算 / C 仿真
```

> 删除旧的 `arch_lookup_min_radius` 单列入口；同步更新 `tests/test_m5_table_radius`（断言 A 最小半径=11.0、最大扫空宽=8.6）。

### 2.3 查表法流程不符合规范层级 —— `app/core/passability.py::run_arc_scene` ✅3

**问题**：规范是"查表优先"，命中即满足；仅当未命中或 E 级才回退验算/仿真。现代码无条件继续按验算口径判定，可能与查表结论冲突。

**改为**三段式判定流程：

```python
def run_arc_scene(bundle):
    ...  # 仿真量测 R_o/R_i、扫空宽度 W_swept 不变
    size_grade = _grade.classify_bundle(bundle)
    transverse_w = _transverse_space_width(bundle, r_in)   # 见 3.1，替代 lane-2σ
    lookup = _grade.arch_lookup_apply(size_grade, r_in, transverse_w, swept_w)

    if lookup == "pass":
        # 规范：查表命中即满足空间可通行性，直接给出结论（但仍跑垂直净空/横向稳定公共校验）
        pass_arc = True
        method = "查表法(表4.3.1)"
    elif lookup == "fail":
        # 任一条件不满足 → 按 B.1 验算口径判定（保留现有 M1/M2/M3 逻辑，用横向空间宽度）
        pass_arc = _verify_arc_b(bundle)     # 抽出现有 outer/inner/width/swept 判定
        method = "验算法(附录B.1)"
    else:  # "fallback" E级/缺数据
        pass_arc = _verify_arc_b(bundle)
        method = "验算法(附录B.1)"
    # 垂直净空 + 横向稳定仍并入最终结论
    res.pass_ok = bool(pass_arc) and vert_ok and lat_ok
```

> `pass_ok` 语义贯穿 `_attach_common_checks` 保持为**逻辑与**（见 2.7）。

### 2.4 圆弧判定口径错误：用 `lane - 2σ` 替代"横向空间宽度" —— `app/core/passability.py` ✅4

**问题**：规范 4.3.1第2款只约束"转弯通道宽度 < 路面宽度"、"扫空空间宽度 < 横向空间宽度（含加宽）"。σ 是外廓与护栏的预留，不应从车道宽两侧简单扣除；B.1.1-1 的 0.5m 安全宽度与 σ 重复计入。

**改为**：
- 新增 `_transverse_space_width()` 按公路等级/设计速度/高度/加宽查表 4.2/4-2~4-8（表值见下），返回横向空间宽度；有加宽则 `+= curve_widening_w`；
- 判定改为三个**独立**判据：

```python
def _verify_arc_b(bundle):
    ra = bundle.road.arc
    r_out, lane = ra.outer_radius, ra.lane_width
    turn_channel_w = swept_w + TURN_SAFE_CLEARANCE            # 转弯通道宽度 B.1.1-1
    road_width     = _road_width(lane, bundle.road)           # 路面宽度（含硬路肩等实际宽度）
    transverse_w   = _transverse_space_width(bundle, r_in)    # 横向空间宽度（查表+加宽）

    width_ok  = turn_channel_w <= road_width                   # ①转弯通道宽度 < 路面宽度
    swept_ok  = swept_w       <= transverse_w                  # ②扫空宽度 < 横向空间宽度
    inner_ok  = (r_i - r_in) >= sigma                          # ③内缘障碍预留（σ用于障碍物而非车道）
    outer_ok  = (r_out - r_o) >= sigma
    return outer_ok and inner_ok and width_ok and swept_ok
```

> `σ` 保留用于"外缘/内缘与护栏等障碍物的预留"判据，不再参与通道宽度双侧扣除。`lane_avail = lane - 2σ` 指标废弃，报告同步删除。

## 3. 与 P0 配套的公共函数

### 3.1 横向空间宽度查表 —— 新增 `app/core/transverse.py`

替代 `lane - 2σ`，按规范 4.2.1/4.2.2 与表 4-2~4-8 计算。先建最小可用的分级化实现（表值以原 PDF 表 4-2~4-8 为准复核，以下为占位规则）：

```python
def transverse_space_width(road: RoadParams, curve_radius: float) -> float:
    """横向空间宽度：按 4.2.2 依次取同向路缘带+硬路肩+行车道，必要时借对向空间。
    有圆曲线加宽时计入加宽(4.3.1第2款)。"""
    w = road.lane_width
    w += road.hard_shoulder_w
    w += road.left_edgeline_w
    if road.median_type == "划线":
        w += road.lane_width            # 划线可借对向行车道
    if road.has_curve_widening:
        w += road.curve_widening_w
    return w
```

> 完整应按公路等级+设计速度+车货高度+圆曲线半径从表 4-2~4-8 取"横向空间宽度"，此为 P1 细化项，接口先立。
